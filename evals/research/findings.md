# Weaknesses found (daftar kelemahan yang ditemukan)

Found by reading the RAG path end to end and by measuring the baseline
([baseline.md](baseline.md)). Nothing here has been fixed: this phase only records findings. The
"Proposed fix" column is input for the modification phase, and each fix has a failing test or a
metric to prove it.

Severity: **H** breaks cards or correctness now · **M** degrades quality or latency, or will break
at scale · **L** hygiene.

| ID | Sev | Weakness | Evidence | Where | Proposed fix | Proof after fix |

| W20 | H | **Every production LLM call is rejected.** OpenCode Go requires an `x-opencode-session` header (a stable session id per conversation) and a descriptive user agent; `make_opencode_go_llm` sends neither. With a valid key, both card paths fail on every request. The README promises that setting the key is enough. | `400 MissingSessionID: Request is missing x-opencode-session`, on all 6 calls of the first real run | `services/generation.py::make_opencode_go_llm` | `default_headers={"x-opencode-session": <per-card id>, "User-Agent": "fishora/<version>"}` | one real card generates |
| W21 | H | **The agent path cannot parse real model output.** With `use_responses_api=True`, `AIMessage.content` is a list of content blocks, not a string. `_expert_node` passes the list to `data["sources"]` and fails. The broad `except` records the result as "expert generation failed". Every expert fails, so every job fails, even though every LLM call succeeded and was billed. `_llm_downgrade` and `_polish` share the same parsing. | nila, real run: 5/5 calls succeeded, card `failed`; content = `[{'type': 'text', 'text': '{…}', 'phase': 'final_answer'}]` | `orchestrator._expert_node`, `_llm_downgrade`, `_polish` | Read `response.text`, then parse tolerantly (W4) | agent success rate with the real LLM |
| W22 | M | **Expert prompts do not require Indonesian.** The system prompt (sync path) mandates Indonesian; the four expert prompts do not. Given English evidence, the expert answered in English ("Mild, delicious flavour."). | debug call, 2026-09-26 | `orchestrator._EXPERT_PROMPTS` | State the output language in each expert prompt; add an automated language check | `english_leak_rate` in `cost_eval` |

## Things that are already right (keep)

- **Verification-gated, species-scoped retrieval.** Purity is 1.00 and unverified rows are never
  returned (tested).
- **Category-first selection.** It gives full category coverage (1.00) for every species despite
  the weak ranking (W8).
- **The fail-closed citation gate** (`KnowledgeGenerator.build_card`). Citation validity is 1.00,
  uncited or foreign citations are rejected, and relational taxonomy always wins (tested).
- **Exact pgvector search.** p95 is 38 ms warm, and an ANN index is unnecessary below about 10k
  rows.
- **The signed approval and ingestion pipeline.** It is deliberately human-gated.

## Hypotheses checked against the baseline

- **H1** — "lexical grading has recall < 0.3". **Refuted in magnitude, confirmed in direction.**
  Recall is 0.59, because Latin names, numbers and loanwords (sashimi, surimi, gelatin) overlap
  across languages. The shared-token false positive was not predicted and is worse than expected.
- **H2** — "4 sequential rounds". **Confirmed:** 4.2 measured.
- **H3** — "scoped Recall@6 ≈ 1.0, so global hit@1 is the informative number". **Confirmed:** 0.989
  and 0.932. The per-category MRR (W8) turned out to be the more useful diagnostic.
